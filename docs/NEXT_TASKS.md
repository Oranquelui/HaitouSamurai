# 配当サムライ Next Tasks

最終更新: 2026-05-18 JST
前提: v1.1.0 は公開済み。次は「レビューしやすさ」「データ信頼性」「安全なワークフロー」を優先する。

## 優先順位の方針

1. 公開リポジトリを見た人が、実装・画面・検証結果をすぐ確認できるようにする。
2. 投資助言に見える機能ではなく、ユーザー自身の確認作業を助ける機能を優先する。
3. データ出典・前提・更新手順を明示する。
4. 有料、ライブデータ、個別化は法務確認後まで進めない。

## P1: データ信頼性と更新手順

### Task 3: 試算データの前提表を追加

目的: 表示データが何を意味し、何を保証しないかを明確にする。

作業候補:

- `docs/DATA_ASSUMPTIONS.md` を追加。
- 以下を記録。
  - 対象データ項目
  - 表示単位
  - 税率前提
  - 静的データであること
  - 更新頻度の想定
  - 一次情報で確認すべき項目

検証:

```bash
git diff --check
npm test
```

受け入れ条件:

- README または PRD から `docs/DATA_ASSUMPTIONS.md` に辿れる。
- 「投資判断前に一次情報確認が必要」という境界が明記されている。

### Task 4: 配当月カレンダーの扱いを明確化

目的: 簡易モデルが実際の支払月保証に見えないようにする。

選択肢:

- A: 現状の簡易モデルを維持し、UI と docs の注意書きを強化する。
- B: 信頼できる source がある銘柄だけ、実際の配当月データを表示する。
- C: 実データが用意できるまで、カレンダー表現を「月別目安」に弱める。

受け入れ条件:

- 実際の支払月を保証しないことが UI と docs の両方で分かる。
- テストが追加または更新されている。

## P1: 開発品質と運用

### Task 5: GitHub Actions CI を追加

目的: main / PR の品質ゲートを自動化する。

作業候補:

- `.github/workflows/ci.yml` を追加。
- Node.js をセットアップ。
- `npm ci`
- `npm run lint`
- `npm test`
- `npm run build`
- `npm audit --audit-level=moderate`

受け入れ条件:

- GitHub Actions が green になる。
- CI が安定したら、main branch protection の required status check 化を検討する。

### Task 6: dependency update policy を追加

目的: Next.js / PostCSS のような依存関係更新を記録しやすくする。

作業候補:

- `docs/DEPENDENCY_POLICY.md` を追加。
- audit 対応、minor update、major update、rollback の方針を書く。

受け入れ条件:

- `npm audit` で脆弱性が出た時の次アクションが docs から分かる。

## P2: ユーザー確認ワークフロー

### Task 7: CSV export を追加

目的: ユーザー自身が選んだ銘柄と試算結果を、外部で確認できるようにする。

ガードレール:

- 推奨銘柄リストとして見せない。
- ユーザーが選択した結果の export に限定する。
- export 内にも非助言の注意書きを含める。

受け入れ条件:

- 選択中の銘柄と入力金額を CSV に出力できる。
- CSV に税率前提と非助言の注記が入る。
- 関連テストがある。

### Task 8: localStorage の保存シナリオ

目的: サーバー保存なしで、利用者が自分の試算条件を再確認できるようにする。

ガードレール:

- 個別助言ではなく、ユーザー自身のメモとして扱う。
- サーバー送信しない。
- 保存内容と削除方法を UI に明示する。

受け入れ条件:

- シナリオ保存、読み込み、削除ができる。
- private / local only の説明がある。
- テストがある。

## P3: 法務確認後まで保留

以下は、法務確認前には実装しない。

- 有料プラン
- リアルタイム市場データ
- 個別化された銘柄提案
- ポートフォリオ最適化
- Buy / Sell / Hold に見える判断表示
- 収益、配当、FIRE 達成を保証するコピー
